# Native reading

First reading slice: owned ordinary paper books, including accessible nested
books. I selects an actual item; Skim/Read uses native obtain and avatar::read.
Unknown books are identified only when the native skim finishes. Known skill
books keep Read once / Read until a level, real helper participation, native
theory experience, morale and chapter marking. No new training rate or free
recipe knowledge. Special-use books, guidebook hints and digital readers have
explicit unsupported reasons and remain separate follow-ups.

CDDA's reading menu gets a scoped external-choice adapter: preserve native
enabled return values, disabled participant information and explicit Cancel.
No generic terminal-menu behavior changes. The existing modal handles choices,
pagination, pause, lost-peer cancellation and connection-bound responses.

CWM 2.25 adds EquipmentAction READ, a seventh action/reason, read-only BookInfo
and canonical ACT_READ progress plus a typed cancel request. Validate lengths,
counts, bounds and activity exclusivity. Inventory and quick-slot actions
revalidate the exact native item at admission and execution. Stale handles,
paused gestures and retransmissions cannot start extra readings.

BookInfo discloses only skim/identified state and the character's native known
book/skill information. Queries don't identify, award XP, alter items, advance
time or RNG. Native reader availability supplies current failure reasons.

I pauses the actor. Close resumes; Interrupt uses native cancel_activity/backlog
rules without refund. Re-reading the same native book resumes an eligible
saved/backlogged activity according to CDDA. Chapter progress is native moves,
not an LLM/client timer; continuous study can start a new chapter, with a fresh
activity token when progress resets. Quit/load persists the actor, not I/menu
pause, matching the accepted current load behavior.

Normal start.sh and an isolated reading demo receive the same implementation.
The fixture contains an unknown short leisure book and a known skill magazine.
Native tests and the actual renderer must cover identification, completed
chapter consequences, cancellation/resumption, paused/stale/duplicate input,
real progress, access cost, canonical save/load and malformed protocol data.
Human readability/comfort checks stay PENDING in the shared manual ledger.
