# Prioritized remediation and next milestone

M5.5 audit is complete and the conformance gate failed. Restore the integrated
product's existing required behavior before starting original M6 (vehicles).
This plan follows the implementation findings, not the previous agents'
completion claims. Each phase needs substantive evidence and a separate
reviewable commit; do not turn a failing probe into a weaker passing assertion.

## Scope and implementation policy

The [current user instruction](../source/project-scope-2026-10-03.md) permits
removing or substantially transforming any CDDA, Luanti or Mineclonia logic
that serves unrelated standalone use. Preserve useful canonical gameplay and
persistence mechanisms, not obsolete integration scaffolding or upstream
functionality for its own sake. For example, redundant supervisors, unrelated
native gameplay paths, unused Lua modules and obsolete CWM messages can be
removed if the combined product becomes simpler or more reliable.

Pinned upstream is a reference/oracle for this audit. Future native tests can
be selected by relevance to required product behavior after changes; record
why a removed capability is outside scope. Save compatibility or simulation
semantics must be verified explicitly when modifying their implementation.
The current audit made no such functional changes.

Use one writer per working tree. Architecture-sensitive boundaries, save
semantics, scheduling, protocol ordering and lifecycle deserve lead review.
Scoped implementation and test work can be delegated in a subsequent phase
if requested, with isolated checkouts and an independent diff review. No
particular model or benchmark claim is a correctness requirement.

## 1. P0 — Restore canonical startup, loading and turns

Addresses F-001/F-003. Distinguish create-world/create-character from loading
an existing selected character. Route loading through the canonical lifecycle
and preserve identity, inventory, position, time and world/master state.
Replace the handwritten partial turn sequence with a shared authoritative
turn/action pipeline. Validate action legality, reach and costs there. Remove
the handshake zombie spawn and synthetic USE-fire behavior.

Acceptance: the native control still passes; inherited avatar/time survive
startup; live wait and movement advance the correct calendar and all required
scheduled systems; rejected actions change no gameplay state. Complete
SAVE-001 with the real bridge and native reloader across position, inventory,
terrain/furniture, monsters, NPCs, vehicles, time and relevant world state,
including restart/reconnect. Preserve the two current failed save preconditions
as regressions. Investigate the native overmap coverage failure separately
and document whether its affected terrain is required by the product.

## 2. P0 — Make transport errors survivable and work bounded

Addresses F-002. Drain buffered complete frames before orderly EOF/HUP.
Validate length before allocating/staging, cap aggregate input/output, and
contain framing/decoding exceptions at the session boundary. Use bounded
nonblocking output queues with explicit overflow/recovery semantics; transport
backpressure must not stop the simulation or visual frame indefinitely.

Acceptance: fragmented and concatenated frames, final-frame-plus-close,
oversized prefixes, truncation, slow readers, disconnect mid-frame and queued
output preserve the process and canonical session. Existing ASan/UBSan probes
pass. Add meaningful queue-limit and bounded-tick/frame checks; retain a
reproducible adverse-peer fixture rather than the historical close-immediately
fuzzer as the sole evidence.

## 3. P1 — Establish the session and recovery protocol

Addresses F-004/F-012. Implement the v1.1 CWM boundary with transport-independent
messages, explicit negotiation, session/player/connection identities,
deduplicated commands, monotonic revisions and contiguous emitted sequences.
Distinguish full snapshots from incremental atomic end-of-turn batches. Define
reset, despawn and resync semantics. Route configured sockets through a single
supervisor and connection lifecycle. Only enable input once a complete accepted
authoritative state has been installed.

Acceptance: unsupported versions are rejected; duplicate commands have one
effect; missing/reordered deltas trigger authoritative resync; reconnect
clears stale state and applies a coherent snapshot. The real bridge gap probe
must pass. Validate transport independence through the interface and a test
backend; another production backend is required only by the specification or
actual deployment needs.

## 4. P1 — Repair projection, validation and ownership

Addresses F-005/F-007. Define one absolute/local coordinate transform for
terrain, entities, vehicles and picking, with explicit origin/recentering,

Acceptance: a small room is visible at zero and nonzero origins, on multiple

threading evidence (TSan where supported or a demonstrated synchronization

until reproduced or ruled out.
