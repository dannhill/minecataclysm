## Prioritized findings

### F-001 — P0: existing saves do not restore the canonical session

[`cwm_main.cpp`](../../cdda/src/cwm/cwm_main.cpp) finds a WORLD directory, then
always creates `avatar(NOW)`, names it Survivor, calls `start_game()` and sets
time to 12 hours. It never uses canonical `game::load(world)`. An inherited
Audit Survivor at 36 hours becomes a different session at 12 hours. Reusing a
directory is not loading its saved character/world state. Repeated startup
can change shared world/master/overmap state while claiming successful reload.

Canonical `game::save` is called, so a file can retain upstream syntax while
the integration still fails semantic persistence. The historical save script
does not compare position, inventory, terrain/furniture, monsters, NPCs,
vehicles, time or relevant world state with a native loader.

The actual 3D test sent three movement requests and received three accepted
acks. Graceful shutdown saved successfully and the pristine public loader
loaded Survivor at the exported absolute position `(-314, 6415, 0)` and time
43,200 seconds. Nevertheless Audit Survivor and its initial 129,600-second
calendar state were lost at startup. These failed preconditions are sufficient
to reject SAVE-001; successfully loading the replacement avatar is narrower
evidence than preserving the inherited session.

### F-002 — P0: malformed or closing peers can destroy the session

[`ipc_transport.hpp`](../../protocol/include/cwm/ipc_transport.hpp) checks
POLLHUP before draining data and returns at recv EOF before extracting buffered
frames. A final valid command/frame can disappear. `FrameDecoder::pop_frame`
throws on a length over 16 MiB, but neither production event loop catches the
exception. A four-byte oversized prefix with the peer held open aborts the
receiver. A premature process abort bypasses graceful authoritative saving.

Receive staging grows before decoding and has no total budget. `send_message`
loops synchronously and polls POLLOUT for 100 ms per stall. A slow peer blocks
the same thread that performs simulation or presentation. The sanitizer probe
demonstrates the behavior; it is not a claim of complete memory-safety coverage.

### F-003 — P0: canonical gameplay rules and command validation are bypassed

[`cwm_server.cpp`](../../cdda/src/cwm/cwm_server.cpp) implements a handwritten
partial turn sequence instead of the canonical CDDA scheduler. Live NONE/wait
processes fields/items/avatar/monsters without incrementing calendar time;
the headless-ticks mode has a different loop and does increment it. NPC,
vehicle, weather and other scheduling semantics are not established.

USE simply adds density-2 fire to a supplied map coordinate and acknowledges
success. Reach, ownership, target legality, normal item/action semantics and
turn costs are not enforced. Handshake itself adds a zombie if none exist.
This is authoritative code executing synthetic rules; process separation
does not make those rules equivalent to CDDA gameplay.

### F-004 — P1: no session, deduplication, ordered batches or resynchronization

Protocol major/minor fields are ignored by the server; state is sent before
negotiation. Replaying command 4242 performs multiple waits with different
world revisions. The schema lacks session/player/connection identities,
ResyncRequest, WorldReset and other v1.1 requirements. Counter allocation
can consume sequence numbers without emitting messages. The bridge never
checks sequence gaps or revision monotonicity, and marks connected before
receiving an accepted handshake and complete snapshot.

Snapshots sometimes omit chunks but still use the full WorldSnapshot type.
There is no atomic end-of-turn delta batch or recovery lifecycle. Reconnect
and full snapshots do not establish removal/clearing of old terrain, entities
or vehicle parts. See [observed protocol](../../protocol/PROTOCOL.md).

### F-005 — P1: terrain, entities and interaction coordinates disagree

The exporter provides horizontal origin plus local coordinates. Terrain and
tile deltas ignore that origin in the bridge, while entities/vehicles add it.
Entity height subtracts `origin.z = player.z - 1`, placing the player one
three-voxel story higher than terrain calculated from the absolute CDDA level.
Recentring the reality bubble therefore changes spatial relationships.
Signed 16-bit presentation coordinates wrap for sufficiently large worlds;
scale, story and eye height are hardcoded.

The 9×9×16 extent exceeds the 132-tile bubble. No explicit clipping/tile-validity
contract exists, and the field scan covers only 128×128. Material string
fallbacks collapse stairs, roofs and layered furniture into generic terrain.

### F-006 — P1: entity and vehicle synchronization is scaffolding

[`cdda_bridge.cpp`](../../luanti/src/cdda/cdda_bridge.cpp) stores/interpolates
entity targets and moves the player camera. It never instantiates monster,
animal or NPC meshes from those states. Lua registration alone creates no
live entity. NPCs are absent from export. Monster IDs are renumbered on every
snapshot; vehicle IDs are process addresses and cannot survive reload.

Vehicle components call `addEmptySceneNode`, with no geometry, and existing
component state is not updated. Absent entities/vehicles are not deleted.
Part names are human-readable strings and velocities are always zero. These
are not verified vehicles or an animated dense urban benchmark population.

### F-007 — P1: semantic validation and ownership/lifecycle are incomplete

FlatBuffers verification permits absent optional pointers that the bridge
dereferences: snapshot origin, entity position, vehicle pivot and part offset.
Validation must enforce required semantic fields, finite/bounded positions,
valid enum values and vector sizes before projection.

This is dynamically reproduced: the real bridge accepts a structurally valid
FlatBuffers snapshot without an origin and exits with SIGSEGV (-11). The primary
result is `evidence/render-camera/BM02/result.json`. Other lifecycle and mesh
threading concerns below remain static findings, rather than reproduced races.

`shutdown()` resets the connection but retains client/scene/GUI pointers,
metrics and visual state. Game destruction deletes that Client. The next
Game can call bridge update/reconnect before new media is ready, using a
retained pointer. `initialize()` discards Impl without explicitly removing
its old scene/GUI objects. These ownership defects are visible in the call
paths; a complete repeated-game/ASan lifecycle reproduction is still required.

CDDA CWM handlers currently run on one thread and serialized buffers cross
the process boundary, which is useful evidence. Luanti mesh workers grab
MapBlock references and copy raw `getData()` outside the queue mutex, while
projection writes `setNodeNoCheck` on the main thread. Queue/refcount locking
is not a proof that node data access is synchronized. Audit this inherited
engine path and CWM update bursts with TSan or an explicit immutable-copy
boundary before declaring threading PASS.

### F-008 — P1: input routing and presentation authority are incomplete

Only WASD enters CWM. Its cooldown subtracts a fixed 1/60 rather than actual
frame time. Picking/inspect/pickup/attack and vertical movement are not wired.
`handleInteract` has no production gameplay caller. AttackRequest is defined
but not dispatched. The bridge hook runs for every Luanti game and uses a
hardcoded socket; connected alone suppresses native movement before full sync.

The pruned Lua mods disable player speed/gravity and independent mapgen, but
ordinary Luanti interaction/session code remains active. A custom game.conf
flag does not establish a complete gameplay-authority fence. The integrated
product needs explicit routing/isolation; the latest user directive permits
removing unrelated standalone Luanti behavior if that is the clearer solution.

### F-009 — P1: fields, time and debug metrics misrepresent capabilities

Field/time messages are ignored by the bridge. Lighting is an ambient estimate
with maximum brightness for any field, rather than a verified canonical light
projection. Luanti's sky is fixed at noon. The overlay's FPS is initialized to
60 and latency to zero and never measured. It is always rendered; F3 retains
the engine's fog toggle. Revisions from any message replace the metric, and
stale chunk counts remain when partial snapshots omit terrain.

### F-010 — P1: tests and documentation overclaim acceptance

The six legacy Python scripts primarily exercise a Python CWM client, copied
LERP/picking/light arithmetic and artifact existence. They do not run the
Luanti bridge. The benchmark sends 100 heartbeats and checks an average; it
does not populate BM01/BM02, measure frame time, P95 input-to-visual, initial
projection, dirty chunks, meshing or GPU work. The fuzzer closes immediately
and treats transport exceptions as completed iterations; EOF handling can
prevent decoding. Its zero-crash result coexists with the stronger oversized
prefix crashing the server.

Root CMake only announces the presence of CDDA/Luanti. Root CTest exits zero
with no tests discovered. Historical cached builds had native tests disabled.
`test_worldgen.py` and patch/fix scripts are production mutators, not tests,
and were not executed as verification.

### F-011 — P1: asset identity is verified; manifest provenance is incorrect

Every one of 42 extracted files hash-matches Mineclonia. However,
character.b3d matches `mcl_armor_character.b3d`, not the declared player model;
the declared `default_grass_side.png` is absent, and local default_grass.png
matches dirt. The generator hardcodes metadata instead of validating paths,
hashes, authors and per-file notices, and covers only a subset of actual files.

Upstream mobs_mc media notices identify its models as GPLv3 by 22i, whereas
the project's zombie mapping declares CC-BY-SA-3.0. mcl_core's README states
MIT for its textures, while the manifest applies CC-BY-SA-4.0. These are
documented source discrepancies, not a resolved licensing determination.
Retain the appropriate notices and reconcile every imported file before release.

### F-012 — P2: launcher configuration, supervision and portability drift

launcher/coordinator sources are identical supervisors. Default Luanti binary
path points under build/bin, while this build outputs luanti/bin. Launcher
socket differs from the hardcoded bridge socket and configuration/user/data
directories are not propagated. Socket existence is treated as readiness;
child exit status is not faithfully returned. Fork failure leaves PID -1,
which the timeout kill path can misuse; signal handlers perform unsafe iostream
work. The startup script uses a fixed delay and shared test paths.

Only POSIX Unix transport exists. Hardcoded home/include/tool/data paths and
unrecorded dependency provisioning prevent clean-machine packaging. These
are combined-product issues; unrelated standalone executables need not be
retained merely to preserve upstream operation.

### F-013 — P2: performance and implementation debt are not measured

Full terrain snapshots scan/serialize 243 chunks after some actions, and
every USE can resend the full projection. There is no dirty-tile journal,
bounded output queue, prioritization or per-frame ingestion budget. Entities
and vehicles are resent rather than synchronized through stable event IDs.
Native mesh tasks are used, but completion/backlog/GPU timing are not measured.
Unused wire events/builders, duplicate supervisors and historical mutators
increase ambiguity. Remove unused paths where useful under the current scope
directive, after covering required behavior with substantive tests.

GCC 11.4, CMake 3.22.1, flatc/headers 24.3.25, Python flatbuffers 25.12.19 and
the existing ~/.local Luanti dependencies. CDDA product build is Release -O3;
the pristine reference oracle is -O0 to limit verification compile cost.

Native reference/source changes are restricted to an external test target.
Do not run historical patch scripts or use shared benchmark save directories.

from the public OCI image without requiring a Docker daemon. It requires
Lua 5.1, argparse and LuaFileSystem under the supplied runtime root; the path
above refers to the audit's private unpacked packages. No full OCI OS execution
is claimed. Raw process exit zero must not override EMPTY test discovery or
the limitations recorded in the evidence index.

See the [prioritized remediation and original M6 proposal](M5.5-remediation.md).
The audit is complete; M5.5 remains FAILED until these product conformance
